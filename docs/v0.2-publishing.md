# V0.2 发布连接、模拟与恢复

交付日期：2026-09-08。版本 0.2.0，dev 分支。本次按用户要求完成本地实现和模拟验收，没有向真实社交平台发送内容，没有生成安装包。四个平台的接口实现不等于真实账号已经验收。

## 启动

在 `content-workbench` 源码目录执行 `npm run dev`，或双击上一级 `启动内容工作台.cmd`。首次使用先运行 `npm ci`。需要 Windows x64、Node.js 22.18 以上和 npm。旧窗口不会自动重载主进程；升级后保存草稿并退出旧窗口再启动。开发版完整功能在 Electron 窗口中使用。

## 不需要凭据的图文模拟

1. 打开自己的测试文件夹，在“账号与定位 → 自动发布连接”选择平台，点击“创建模拟账号与目标”。
2. 在下方连接表单选择新目标、选择“成功”等场景，保存配置，然后“检查发布连接”。卡片应显示“连接已检查 · 仅模拟”。
3. 导入一张合成图片，新建内容、添加相同平台版本，填写正文并选择图片。保存草稿，标记就绪。
4. 点击“安排发布”，发布方式选“本地模拟”，勾选模拟目标和确认框，设定现在或稍后的时间，创建任务。
5. 在“发布记录”查看结果与“操作记录”。扫描周期 15 秒；模拟回执以 `mock-` 开头，始终显示“模拟 · 无外部发送”。
6. 重启后已完成任务保持完成。试用“最终提交超时”场景时，任务进入结果未知；“核实平台结果”不会再次发送。没有凭据时可继续用原来的辅助发布包。

模拟场景包含成功、处理中、上传失败、最终提交超时、限流、授权失效、内容拒绝。Mock 只能绑定专用模拟账号，模拟目标与真实目标不能混排。

## 真实连接怎么配置

先在“账号与定位”建立对应账号和目标，再进入“自动发布连接”。保存连接会暂停旧任务；检查连接只读取身份，不发送帖子，也不证明全部发帖权限可用。只有安排时选择“自动发布”并确认的任务才会调用最终发布接口。

| 连接 | 账号 / 目标 | 本版实现 | 需要填写 |
|---|---|---|---|
| Discord | Webhook 对应频道；目标类型 channel | 单条正文与图片附件、关闭提及、等待消息回执 | 官方 Webhook URL；频道 ID 可留空由检查确定 |
| X | 用户账号；目标 profile | 用户 OAuth 2.0 单条图文、媒体 ID、非提交阶段令牌刷新 | 用户 access token、可选 refresh token 与公开客户端 ID、可核对的用户 ID |
| Instagram | professional / business / creator | Instagram Login 路径的 JPEG 单图 / 轮播、容器处理、公开回执查询 | 专业账号令牌与 ID、Graph API 版本、媒体出口及其令牌 |
| Facebook | 账号类型 page；目标类型 page | Page 图片准备、正文或链接帖子、公开状态查询 | 目标 Page 的访问令牌与 Page ID、Graph API 版本 |

Facebook 连接检查必须读到 Page 分类，不接受个人用户冒充 Page。Instagram 个人账号、X 串帖 / 视频、Discord 论坛、Facebook Reel、Instagram Reel / Story 继续辅助发布。Instagram 地点 / 替代文本和 Facebook 自定义受众 / 链接标题尚未接入自动提交，填有这些字段时会提示转辅助，避免静默丢失。

本版的图片数量和大小校验是保守的产品边界，不能代替账号当前配额。Graph 版本初值为 v24.0，可在连接表单调整，不宣称它永远是最新版。X 费用、应用权限和额度须从实际开发者后台核对，本版不写死套餐价格。X 令牌刷新按公开客户端流程实现；需要 client secret 的 OAuth 客户端请先在外部完成令牌获取，不把 client secret 填成客户端 ID。

原生平台定时没有启用，所有自动排期都需要本机应用运行；因此本版不存在已经创建的原生排期及其撤销回执。连接检查通过后仍显示“真实发布未验证”；未来收到真实回执只记录该目标、该内容类型、任务 ID 和时间，不把其他类型自动标成已验收。

## Instagram 媒体出口契约

这是可配置的媒体存储接口，仓库没有附带已部署的云存储服务。使用者需要提供符合下面契约的 HTTPS 服务；没有服务时使用模拟或辅助发布。

- `POST <endpoint>/objects`：Bearer 媒体出口令牌；请求字段 `name, sha256, contentType, bytes, expiresInSeconds: 86400`。返回 `id, uploadUrl, url, expiresAt`。
- `PUT uploadUrl`：上传固定快照的图片字节，仅带图片 Content-Type，不传账号令牌或出口令牌。
- `url` 是 Instagram 可读取的临时公开 HTTPS 地址，不允许用户名密码或查询参数；不能把私密签名写进项目文件。服务应使用随机对象路径并强制 TTL 清理。`uploadUrl` 可使用只供本次上传的签名，不落盘。
- 有效期至少剩余 5 分钟；使用前逐项 HEAD 检查公开地址。地址无效或剩余不足 1 分钟时不会调用最终发布。
- 每次上传和创建容器后保存进度；轮播保持素材顺序，只有容器 FINISHED 后才提交。已发布后调用 `DELETE <endpoint>/objects/:id`，携带媒体出口令牌；404 也视作已清理。
- 结果未知期间保留媒体供核实，依赖出口 TTL 最终清理；发布后清理失败可以在任务中重试。明确未发送的任务重新安排时先清理旧临时对象，再重新准备。创建对象后进程崩溃产生的孤立对象由出口 TTL 处理。

## 后台与恢复

“设置与备份 → 后台发布项目”显示最近项目的未完成数量。切换界面项目不改变任务归属；重启会重新打开已启用发布连接的登记项目。点“隐藏到托盘，继续处理”可保留草稿和后台队列；双击托盘图标返回。完全退出会停止本地处理，不设置 Windows 开机自启动。

“停止管理并暂停待执行任务”会停用项目连接并暂停未发送任务。当前请求正在执行时，需要等待它结束；已提交但结果不明的任务保持原状态。重新检查连接后，已暂停任务仍需逐项重新安排，不会集中补发。

| 状态 / 故障 | 行为与操作 |
|---|---|
| 到期超过 5 分钟，含休眠恢复 | 标记需要处理，不补发；确认内容后重新安排 |
| 上传失败 / 明确限流 | 最多 3 次尝试，退避并遵守 Retry-After；失败后可重新安排或转辅助 |
| 授权失效 | 停用该账号连接并暂停未发送任务，更新凭据、检查后逐项处理 |
| validating / preparing 中断 | 租约过期后恢复媒体准备记录，提交前再次检查账号和连接 |
| submitting 中断 / 超时 | 结果未知，禁止盲重发；优先核实 ID，缺 ID 时去平台人工检查 |
| accepted / 提交后 processing | 继续查询公开结果，接收不等于公开；不会调用第二次最终提交 |
| published | 永不自动重发；单个目标失败不会改变成功目标 |
| 换连接远端 ID | 旧任务不能用“重试”改投新目标，应创建新排期并确认 |
| 备份恢复 | 未发送任务暂停，已提交任务保留待核实，成功回执保留；凭据需在本机另行配置 |

人工回填仍与平台核实区分。结果未知时，只有在平台确认事实后才回填；回填本身不把连接标成已验证。每次处理前取得 120 秒租约，运行时续租；单账号串行、应用内总并发 2。提交意图和事件在外部请求前写入 SQLite，无法判断结果时选择核实而不是声称“恰好一次”。

## 凭据与升级

平台凭据在 Electron `userData/publishing/credentials.json` 中用系统 `safeStorage` 加密；界面只返回有无凭据，不返回原值。它不位于业务项目、不进发布快照或业务备份。常规 Windows dev 用户数据通常在 `%APPDATA%/content-workbench`，设置了 `WORKBENCH_USER_DATA` 时使用指定位置。手工保存的私密文件仍放仓库忽略的 `local-private/`，见 [私密文件说明](local-private-files.md)。

首次可写打开项目将 SQLite user_version 升到 2，在事务中增加发布事件与迁移表，保留原 jobs / runs / sessions。项目 Markdown / JSON schema 仍为 1，旧任务保持人工发布方式。不要用旧版软件继续写升级后的数据库；需要回退时先备份，并使用升级前的备份恢复。不同电脑或 Windows 身份无法解密旧凭据时，在连接表单重新填写，不需要改业务内容。

## 官方接口依据与待办

- [Discord Execute Webhook](https://docs.discord.com/developers/resources/webhook)：附件与 wait 回执。
- [X 创建帖子](https://docs.x.com/x-api/posts/create-post)、[X 媒体上传](https://docs.x.com/x-api/media/upload-media)：用户授权、媒体 ID。
- [Instagram Login 内容发布](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/content-publishing/)、[Meta 官方接口集合](https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api)：登录路线与容器流程须按实际账号再次核对。
- [Facebook Page 帖子](https://developers.facebook.com/docs/pages-api/posts/)：Page 权限与图文流程。Meta 开发者页面本次读取受限，未用社区示例替代真实账号证据。

以上为接口依据，不是生产连接认证。待有获准目标后，逐平台核对应用审核、账号权限、费用配额、图文效果、远端 ID 与公开链接，并记录验证日期；本次不作这项外部验收。
