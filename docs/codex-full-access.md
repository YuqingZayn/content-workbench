# 内置 Codex：Full Access

在仓库目录运行 `npm run dev`，连接本机 Codex CLI，然后打开一个内容主题。右侧显示 `Full Access`，默认选择“执行任务”。可以直接输入：

- “修改 `E:\我的项目\README.md`，补充启动方法。”
- “检查内容工作台源码，修复这个页面的问题，并运行相关测试。”
- “读取这个项目的资料，在指定目录新建一份整理后的文档。”

完全访问允许调用工具、运行命令、联网和读写当前系统账号可访问的本机文件；工作目录默认是当前业务项目，但不是访问范围的边界。操作系统账号权限、文件占用和组织策略依然有效。软件不会自动取得管理员权限。

## 执行任务与起草版本

**执行任务（默认）**：可用整个主题或所选版本作为参考，无平台版本也能发起。Codex 直接执行用户要求，完成后在对话中说明结果；结果文字不会自动覆盖帖子正文。任务完成会刷新当前项目，文件修改仍保留在实际操作的位置。

**起草版本**：选择目标平台版本，输入文案要求。Codex 同样可以使用工具，最终返回结构化文案，应用校验版本 ID、素材绑定与并发修改后写回。点击起草、改写、翻译等快捷动作会切换到此方式。文案冲突保留建议供合并。

两种方式各自复用会话；升级前的只读会话不再复用，历史运行记录仍保留。已有运行不会在断线或重启后自动重放。停止按钮用于中断当前任务，已执行的文件修改不会因此自动撤销。

## 权限配置

软件在 `thread/start`、`thread/resume` 中设置 `sandbox: "danger-full-access"`、`approvalPolicy: "never"`；在每次 `turn/start` 中再次设置 `sandboxPolicy: { type: "dangerFullAccess" }` 和 `approvalPolicy: "never"`。本机 CLI 返回的实际线程权限不匹配时，软件会显示错误，不会悄悄退回只读模式。

旧的“禁止工具、命令和文件修改”提示已移除。文件与命令审批如仍到达客户端，会按已授权的 Full Access 策略响应，且必须属于当前活动线程及轮次。凭据或其他缺失输入不能由权限设置代替。

这项设置针对应用发起的会话，不改写用户全局 `~/.codex/config.toml`，也不关闭 Electron 页面沙箱。`local-private/` 和 `.local/` 的 Git 忽略规则继续生效；这些目录对具有完全访问权限的 Codex 可读写。

配置依据为 [OpenAI App Server 文档](https://learn.chatgpt.com/docs/app-server)，具体字段与本机 Codex CLI 0.153.3 生成协议对照。

## 本地验证

```powershell
npm run verify:codex-access
```

此命令使用已登录的真实 Codex，执行两轮文件写入验证。脚本在 `.local/codex-full-access/` 新建隔离项目和测试文件，要求 Codex 修改项目内文件和项目外的同级文件，然后读回校验；第二轮恢复同一会话，验证权限仍然有效。结果保存在忽略目录中。该验证会使用 Codex 额度，常规自动化测试使用模拟连接。
